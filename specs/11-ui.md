## 1. Цель

GUI, который проводит пользователя по сценарию SPEC-00 §1.2: настроить скан → увидеть
прогресс → разобраться в находках (что, почему, сколько весит) → выбрать → сохранить бэкап.
UI — тонкий слой над `sk-engine`. Бизнес-логики во фронтенде нет, кроме фильтрации и
отображения.

## 2. Область

### 2.1 Входит
- Tauri 2: команды, события, состояние, capabilities, CSP.
- React-приложение: экраны, навигация, состояние, i18n, темы, доступность.
- Генерация TS-типов (specta/tauri-specta).

### 2.2 Не входит
- Экран восстановления: описан в SPEC-13 §4.7 (здесь только слот в навигации).
- Сборка и дистрибуция: SPEC-14.
- Логика скоринга и выбора по умолчанию: SPEC-09 (UI только показывает и меняет выбор).

## 3. Требования

### 3.1 Функциональные
- **FR-11-01** — Экраны: Welcome/настройка скана, Прогресс скана, Результаты, Настройки (в т.ч. LLM), Бэкап (настройка → прогресс → итог), Журнал (issues/логи), О программе.
- **FR-11-02** — Результаты отображают до 100 тыс. строк без подтормаживаний (виртуализация). Группировка «Категория → Приложение → Находка» или «Приложение → Находка», переключаемая.
- **FR-11-03** — Tri-state чекбоксы на уровне групп. Выбор хранится на бэкенде (`update_selection`), фронт держит оптимистичную копию.
- **FR-11-04** — Фильтры: категория (мульти), только выбранные, только sensitive, только неизвестные, минимальный/максимальный размер, источник evidence (rule/games/system/heuristic/llm). Поиск по названию, приложению, пути-шаблону (fuzzy, клиентский).
- **FR-11-05** — Сайдбар деталей: цель (путь-шаблон + resolved, кнопка «Открыть в Проводнике»), статистика, все `Evidence` (текст через i18n `message_key` + args, источник, уверенность), разложение `Score.components` (горизонтальные бары), теги, sensitivity-предупреждение, `requires_elevation`.
- **FR-11-06** — Раздел «Не распознано» (`ScanReport.unknown_summaries`): список папок со сводкой (размер, топ-расширения, свежесть, маркеры) и действием «Добавить в бэкап» (создаёт находку с `EvidenceSource::User`, через `add_user_finding`) или «Игнорировать».
- **FR-11-07** — Sensitive-находки (`Sensitivity::High`) помечены иконкой-замком. При выборе хотя бы одной такой находки экран бэкапа рекомендует шифрование (баннер + переключатель включён по умолчанию).
- **FR-11-08** — LLM-настройки: режим (off/local/cloud), провайдер, endpoint, модель, API-ключ (сохраняется в Credential Manager, SPEC-08), кнопка «Проверить подключение» (`llm_health_check`), **превью отправляемых данных** (`llm_preview` — пример JSON, который уйдёт в модель, для 3 случайных неизвестных папок).
- **FR-11-09** — Экран бэкапа: выбор папки назначения (нативный диалог), имя, формат zip/dir, шифрование (пароль ×2, индикатор силы), оценка (`estimate_backup`): объём, примерный размер архива, свободное место, ФС, блокеры (красным, кнопка «Начать» неактивна), предупреждения (жёлтым).
- **FR-11-10** — Прогресс бэкапа: байты и файлы, текущий файл (шаблон), скорость, ETA, кнопка «Отмена» (с подтверждением внутри страницы, без `confirm()`). После записи, если есть заблокированные файлы, показывается панель «Закройте X и нажмите Повторить» (SPEC-10 FR-10-06) с кнопками «Повторить» и «Пропустить и завершить».
- **FR-11-11** — Итог: статус, путь (кнопка «Открыть папку»), «Открыть отчёт» (`report.html` в браузере по умолчанию через `open_path`), сводка issues.
- **FR-11-12** — i18n: ru и en. Язык по умолчанию определяется по `navigator.language` / языку UI Windows (`Environment.os.ui_language`), переключается в настройках (`config.ui.language`).
- **FR-11-13** — Темы: светлая, тёмная, системная (`prefers-color-scheme`), `config.ui.theme`.
- **FR-11-14** — Доступность: всё управляется с клавиатуры (Tab/Shift+Tab, стрелки в дереве, Space — чекбокс, Enter — детали, `/` — фокус поиска, Esc — закрыть сайдбар), ARIA-роли `tree`/`treegrid`, видимый фокус, контраст WCAG AA.
- **FR-11-15** — При закрытии окна во время скана или бэкапа показывается подтверждение (внутристраничный диалог). Выход отменяет задачу корректно (SPEC-01 FR-01-04).
- **FR-11-16** — Если при запуске найден `.partial` от прерванного бэкапа или предыдущий скан (< 24 ч), Welcome предлагает «Открыть результаты прошлого скана».

### 3.2 Нефункциональные
- **NFR-11-01** — Время от клика «Сканировать» до появления экрана прогресса ≤ 150 мс.
- **NFR-11-02** — Скролл результатов 60 fps на 100 тыс. строк (TanStack Virtual, overscan 10).
- **NFR-11-03** — Бандл фронта ≤ 1.5 МБ gzip. Без внешних CDN, всё локально.
- **NFR-11-04** — Минимальное окно 960×600, адаптивность до 1280×720 без горизонтального скролла. HiDPI.
- **NFR-11-05** — Никаких сетевых запросов из WebView (CSP `connect-src ipc: http://ipc.localhost`).

## 4. Дизайн

### 4.1 Публичный API: Tauri-команды

Все команды объявлены в `app/src-tauri/src/commands/*.rs` с `#[tauri::command]` +
`#[specta::specta]`, TS-обёртки генерируются `tauri-specta` в `app/src/bindings.ts`.
Ошибки — `CmdError { code: String, message_key: String, args: BTreeMap<String,String> }`.

- `open_path` **не принимает произвольный путь** от фронта: только ссылки на известные объекты (безопасность, §4.8).
- `JobId` — `Uuid`. Одновременно активна максимум одна задача скана и одна задача бэкапа. Вторая получает `CmdError{code:"busy"}`.

### 4.2 События
- Один канал: `sk://event`, полезная нагрузка `JobEvent { job: JobId, event: Event }` (`Event` — SPEC-01 §4.5).
- Дополнительные: `sk://job-finished { job, outcome: "ok"|"cancelled"|"error", error?: CmdError }`.
- Фронт подписывается через `events.skEvent.listen()` (tauri-specta typed events).

### 4.3 Rust-сторона: состояние

- Выбор сохраняется в `scans/<scan_id>.selection.json` при каждом изменении (debounce 500 мс), чтобы переживать перезапуск.

### 4.6 Состояние фронта

```ts
// store/app.ts
type Screen = 'welcome' | 'scanning' | 'results' | 'backup-setup' | 'backup-progress' | 'summary' | 'settings' | 'journal' | 'about' | 'restore';
interface AppStore { screen: Screen; go(s: Screen): void; activeJob?: { id: string; kind: 'scan' | 'backup' } }

// store/results.ts
interface ResultsStore {
  grouping: 'category' | 'app';
  filters: { categories: Category[]; onlySelected: boolean; onlySensitive: boolean; onlyUnknown: boolean;
             minBytes?: number; maxBytes?: number; sources: EvidenceKind[] };
  query: string;
  selected: Set<FindingId>;          // оптимистичная копия; источник истины — бэкенд
  focusedId?: FindingId;
}
```
- Изменение выбора: локальное обновление → батч (debounce 150 мс) → `update_selection` → при ошибке откат и тост.
- Производные данные (дерево, суммы по группам) — `useMemo` поверх `report.findings` + filters. Суммы групп считаются по отфильтрованному набору.
- Tri-state: группа `checked` — все дети выбраны, `indeterminate` — часть, `unchecked` — ни одного. Клик по группе в `indeterminate` выбирает всех.

### 4.7 i18n
- Ключи: `screen.*`, `category.<snake>`, `evidence.*` (совпадают с `message_key` SPEC-02 §2.5), `issue.*`, `error.<code>`.
- Ресурсы: `src/i18n/<lang>/<файл>.json`, где `<файл>` — первый сегмент ключа (`rules`, `issue`, `evidence`, `games`, `about`, `category`, `screen`, `error`, …). Файл содержит вложенные объекты без этого сегмента; при загрузке все файлы языка сливаются в один namespace i18next (`translation`) под ключом верхнего уровня `<файл>`, `keySeparator` — `.`, поэтому полный ключ `<файл>.<путь>` совпадает с ключом бэкенда (`rules.json` → `{"chrome": {"profiles": …}}` → `rules.chrome.profiles`). Сегменты ключа не содержат `.` и `:`.
- Тексты: интерполяция `{{arg}}` по `message_args`; необязательные аргументы (например `line`) в тексте не используются — i18next оставляет отсутствующий `{{arg}}` как есть. Аргумент-перечисление переводится вложенной ссылкой `$t(<полный ключ>.{{arg}})` (i18next интерполирует до вложения): `issue.rules.from_json_skipped` → `issue.rules.from_json_skip_reason.<reason>`. Рендерер `report.html` (SPEC-10 §4.8) поддерживает то же подмножество: `{{arg}}`, `$t(…)`, плюральные суффиксы.
- Бэкенд отдаёт только ключи и аргументы, тексты живут во фронте. Исключения: `evidence.llm.reason` (текст от модели) и `report.html` (рендерится на бэкенде, SPEC-10 §4.8 — ресурсы дублируются в `sk-backup/templates/i18n`; общий источник — `app/src/i18n`, копируется build-скриптом).
- Проверка полноты: тест, что множества ключей ru и en и аргументы `{{…}}` каждого ключа совпадают, что все `message_key`, встречающиеся в Rust (`grep` по `"evidence.`, `"issue.`), есть в ресурсах и что ссылки `$t(…)` разрешаются (SPEC-12). До `xtask i18n-check` (T-12-09) ключи `sk-rules` проверяет `crates/sk-rules/tests/i18n_keys.rs` (SPEC-04 T-04-11).
- Плюрализация: i18next plural (ru: one/few/many).
- Заголовок находки: UI переводит каждую часть `Finding.title`, разделённую ` — `, если это ключ i18n; иначе показывает как есть (SPEC-04 §4.2, `TITLE_LABEL_SEPARATOR`).
- Форматирование размеров: `Intl.NumberFormat` + собственные единицы (КБ/МБ/ГБ, двоичные, подпись «ГБ»).

### 4.8 Безопасность Tauri
- Capabilities (`app/src-tauri/capabilities/main.json`): только `core:default`, `core:event:default`, `core:window:allow-close`, `dialog:allow-open` (выбор папки), и собственные команды приложения. **Не подключаются**: `shell` (кроме внутреннего использования на Rust-стороне), `fs`, `http`, `opener` с произвольными путями.
- `open_path` реализован на Rust: `explorer.exe /select,"<path>"` или `ShellExecuteW(open)` для известных путей из состояния, а не из аргументов фронта.
- CSP в `tauri.conf.json`:
  `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src ipc: http://ipc.localhost; object-src 'none'; frame-ancestors 'none'`.
- `devtools` выключены в release. Контекстное меню браузера отключено в release.
- Пароль шифрования передаётся одной командой `start_backup`, на Rust-стороне сразу оборачивается в `SecretString`, во фронте хранится только в состоянии компонента и очищается после отправки.
- API-ключ никогда не возвращается фронту (`get_config` отдаёт `api_key_set: bool`).

### 4.9 Прочее поведение окна
- Одно окно, заголовок нативный. Размер и позиция запоминаются (`tauri-plugin-window-state`).
- Второй экземпляр активирует первое окно (`tauri-plugin-single-instance`). Плагин отвечает только за активацию окна; взаимоисключение с CLI обеспечивает `sk-core::win::single_instance::acquire()` (SPEC-01 §4.10), который GUI вызывает при старте и держит `InstanceGuard` в состоянии Tauri всё время работы. При `AlreadyRunning` без живого окна GUI (например, идёт CLI `backup`) показывается ошибка и приложение завершается.
- Уведомление в панели задач (прогресс в иконке taskbar через `ITaskbarList3` — желательно).

## 5. Ошибки и граничные случаи

| Ситуация | Поведение |
|---|---|
| Команда вернула `CmdError` | Тост с `t(error.<code>)` + ссылка «Подробнее» → Журнал. |
| Скан завершился с ошибкой | Экран прогресса показывает ошибку и кнопки «Повторить» и «Открыть журнал». |
| 0 находок | Пустое состояние с объяснением и ссылкой на «Не распознано» / настройки скана. |
| Отчёт очень большой (> 50 МБ JSON) | `get_report` отдаёт полный отчёт. Если парсинг превышает 1 с, спинер. Для > 200 тыс. находок — открытый вопрос §9 (пагинация). |
| LLM недоступна (health-check fail) | Бейдж «Недоступно» + причина (нет Ollama, нет модели, 401). Скан с `llm=local` всё равно разрешён: фаза Classify пропустится с issue. |
| WebView2 отсутствует | Обрабатывается до создания окна: SPEC-14 §4.3. |
| Закрытие окна во время бэкапа | Внутристраничное подтверждение → отмена задачи → ожидание завершения (≤ 2 с) → выход. |
| Смена языка | Мгновенно, без перезапуска. |

## 6. Тестирование

- **Rust (`app/src-tauri`):** unit-тесты команд с фейковым `AppState` (без окна): `update_selection` считает `SelectionTotals`, `open_path` отклоняет неизвестные id, `busy` при второй задаче.
- **Фронт (vitest + RTL):**
  - построение дерева и tri-state логика (`buildTree(findings, grouping, filters)`);
  - фильтры и поиск;
  - редьюсер прогресса (события → состояние фаз);
  - `format.ts` (байты, ETA, плюрализация ru);
  - i18n: совпадение ключей ru/en.
- **Производительность:** тест рендера 100 тыс. строк (jsdom считает только видимые строки ≤ 60).
- **E2E (SPEC-12 §e2e):** smoke — запуск → скан фикстуры → выбор → бэкап в temp → итог.
- **Доступность:** `@axe-core/react` в dev-режиме, 0 serious/critical на основных экранах.
