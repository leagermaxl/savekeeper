# Чек-лист ручной проверки T-04-07

| Поле | Значение |
|---|---|
| Основание | SPEC-04 T-04-07 «Готово, когда»: правила §4.7.1–§4.7.2 на машине разработчика; SPEC-01 §8 (Ctrl+C); SPEC-03 §8 (OneDrive «только онлайн», junction'ы профиля) |
| Когда выполнять | один раз перед закрытием T-04-07; результат (отметки и цифры, без личных путей) — в описание PR |
| Где | реальный Windows-ПК разработчика, обычный пользователь (без «Запуск от имени администратора»), PowerShell 7 (`pwsh`) |

Принцип P1: SaveKeeper только читает. Во время проверки ничего не удалять, не перемещать и не
«чинить» в профиле, чтобы улучшить результат. Отчёты содержат реальные пути — в репозиторий
их не коммитить.

## 0. Подготовка

```powershell
# В корне репозитория
cargo build --release -p sk-cli
# Отдельная папка не на диске C: (рядом с exe появится savekeeper-data с логами)
New-Item -ItemType Directory E:\sk-manual -Force | Out-Null
Copy-Item .\target\release\savekeeper-cli.exe E:\sk-manual\
Set-Location E:\sk-manual
$repo = '<путь к репозиторию>'
```

Перед сканом открыть Chrome (или другой Chromium-браузер) и Firefox, если они установлены:
их находки должны получить тег `app-running`.

## 1. Правила браузеров и dev-окружения (§4.7.1–§4.7.2)

### 1.1 Встроенные файлы валидны

```powershell
.\savekeeper-cli.exe rules validate "$repo\rules"
"exit code: $LASTEXITCODE"
```

Ожидается: в stdout пусто, в stderr `7 rule files checked, 0 errors, 0 warnings`, код `0`.

### 1.2 Скан и находки правил

```powershell
.\savekeeper-cli.exe scan --llm off --out t0407.json --pretty
"exit code: $LASTEXITCODE"          # 0 или 3 (3 — есть предупреждения, смотреть issues)

$ids = Get-Content "$repo\rules\browsers.yaml", "$repo\rules\dev.yaml" |
  Select-String '^\s*- id: (\S+)' | ForEach-Object { $_.Matches[0].Groups[1].Value }
$r = Get-Content t0407.json -Raw | ConvertFrom-Json
$rows = foreach ($f in $r.findings) {
  $rid = ($f.evidence | Where-Object { $_.source.kind -eq 'rule' } | Select-Object -First 1).source.rule_id
  if ($ids -contains $rid) {
    [pscustomobject]@{
      rule   = $rid
      title  = $f.title
      cat    = $f.category
      sens   = $f.sensitivity
      notes  = $f.notes_key
      tags   = $f.tags -join ','
      target = if ($f.target.resolved) { $f.target.resolved } else { $f.target.key }
      files  = $f.stats.file_count
      MB     = if ($f.stats) { [math]::Round($f.stats.total_bytes / 1MB, 2) }
      locked = $f.stats.locked_files
    }
  }
}
$rows | Sort-Object rule, target | Format-Table -AutoSize -Wrap
"no findings: " + (($ids | Where-Object { $rows.rule -notcontains $_ }) -join ', ')
$r.issues | Where-Object source -eq 'rules' | Format-Table severity, message_key, path -AutoSize -Wrap
```

Для каждого правила отметить: программа установлена / находка есть / путь и объём верны.
Правило установленной программы без находки или находка неустановленной программы — пропуск
(задача на правило).

| Правило | Что проверить |

## 2. Ctrl+C на реальном скане (SPEC-01 §8)

```powershell
Remove-Variable LASTEXITCODE -ErrorAction SilentlyContinue
.\savekeeper-cli.exe scan --llm off --out cancel.json
```

Через 2–3 секунды после старта, пока идёт прогресс (если скан успевает закончиться раньше,
добавить `--roots D:\`), нажать **Ctrl+C** и засечь время по секундомеру.
Затем отдельной командой:

```powershell
"exit code: $LASTEXITCODE"
Test-Path .\cancel.json
```

Ожидается: приглашение PowerShell возвращается не позже чем через 1 с после Ctrl+C, в stderr
`cancelled`, код `2`, `cancel.json` не создан (`False`).

## 3. OneDrive «только онлайн» не гидрируются (SPEC-03 §8)

Нужна папка OneDrive с файлами в состоянии «только онлайн» (облачный значок; при
необходимости «Освободить место» в контекстном меню проводника). Лучше папка внутри
Documents/Desktop, если они перенаправлены в OneDrive, или внутри `$env:OneDrive`.

```powershell
$cloud = '<папка OneDrive с файлами «только онлайн»>'
function Get-OnlineOnly($dir) {
  # FILE_ATTRIBUTE_RECALL_ON_DATA_ACCESS (0x400000): file content is not on disk
  (Get-ChildItem -LiteralPath $dir -Recurse -File -Force -ErrorAction SilentlyContinue |
    Where-Object { ([int64]$_.Attributes -band 0x400000) -ne 0 }).Count
}
$before = Get-OnlineOnly $cloud; "online-only before: $before"
```

Затем выполнить скан из §1.2 (или повторить его) и `.\savekeeper-cli.exe debug summarize $cloud --pretty`,
после чего:

```powershell
$after = Get-OnlineOnly $cloud; "online-only after: $after"
```

Ожидается: `$before` > 0 и `$after` = `$before`; в проводнике у файлов по-прежнему облачный
значок (не зелёная галочка); OneDrive во время скана не показывал загрузку файлов.

## 4. Junction'ы профиля не дают двойного счёта (SPEC-03 §8)

### 4.1 Ни один путь отчёта не идёт через junction

```powershell
$docs = [Environment]::GetFolderPath('MyDocuments')
$links = Get-ChildItem -LiteralPath $HOME, $env:LOCALAPPDATA, $docs -Force -Directory `
           -Attributes ReparsePoint -ErrorAction SilentlyContinue |
         Where-Object LinkType -eq 'Junction' | ForEach-Object FullName
"junctions: $($links.Count)"       # обычно 10+ (Application Data, Local Settings, My Documents …)
$r.findings | ForEach-Object { $_.target.resolved } | Where-Object {
  $p = $_; $p -and ($links | Where-Object { $p -eq $_ -or $p.StartsWith("$_\", 'OrdinalIgnoreCase') })
}
```

Ожидается: последняя команда ничего не выводит.

### 4.2 Размеры не больше реальных

PowerShell 7 при `-Recurse` не заходит в junction'ы, поэтому его счёт — верхняя граница
(глобальные исключения SaveKeeper могут дать меньше, но не больше).

```powershell
# Находки-папки без include/exclude
$r.findings | Where-Object {
  $_.target.kind -eq 'file_set' -and $_.stats -and
  $_.target.include.Count -eq 0 -and $_.target.exclude.Count -eq 0
} | ForEach-Object {
  $files = Get-ChildItem -LiteralPath $_.target.resolved -Recurse -File -Force -ErrorAction SilentlyContinue
  $bytes = [int64]($files | Measure-Object Length -Sum).Sum
  [pscustomobject]@{
    title = $_.title; report_files = $_.stats.file_count; real_files = $files.Count
    report_MB = [math]::Round($_.stats.total_bytes / 1MB, 1); real_MB = [math]::Round($bytes / 1MB, 1)
    ok = $_.stats.file_count -le $files.Count -and $_.stats.total_bytes -le $bytes
  }
} | Format-Table -AutoSize

# Папки с junction'ами внутри: Documents (My Music, My Pictures, My Videos) и LocalAppData
# (Application Data → сама на себя)
foreach ($dir in $docs, $env:LOCALAPPDATA) {
  $s = .\savekeeper-cli.exe debug summarize $dir | ConvertFrom-Json
  $real = Get-ChildItem -LiteralPath $dir -Recurse -File -Force -ErrorAction SilentlyContinue
  $realBytes = [int64]($real | Measure-Object Length -Sum).Sum
  "{0}: summarize {1:N0} files / {2:N1} MB, truncated={3}; real {4:N0} files / {5:N1} MB" -f `
    $dir, $s.file_count, ($s.total_bytes / 1MB), $s.truncated, $real.Count, ($realBytes / 1MB)
}
```

Ожидается: во всех строках `ok = True`; у `debug summarize` (при `truncated=False`) число файлов
и объём не больше реальных. Двойной счёт выглядел бы как значения, кратно больше реальных.
