# SaveKeeper

Портативная программа для Windows 10/11 (Rust + Tauri 2 + React/TS), которая перед переустановкой
системы находит и сохраняет важные файлы: сохранения игр, настройки программ, пользовательские
данные, окружение разработчика, системные настройки.

## Работа по спекам (обязательно)

- Вся разработка ведётся по спекам в `specs/`. Точка входа — `specs/00-master.md`, особенно §2 (принципы), §7 (соглашения) и §8 (процесс).
- Код пишется только по спекам в статусе `approved` или выше (поле «Статус» в шапке спеки). Код по `draft`-спекам не писать.
- Перед задачей прочитай её спеку целиком и §4.1 (публичный API) всех спек из её «Зависит от».
- Бери первую невыполненную задачу `T-XX-NN`, у которой выполнены все зависимости. За раз выполняй одну задачу.
- Если спека неверна, неполна или противоречит другой спеке, остановись и предложи правку спеки. Не отклоняйся от спеки молча и не меняй утверждённые спеки без согласования (SPEC-00 §8.1).
- После задачи:
  - отметь `[x]` у задачи в спеке;
  - проверь Definition of Done (SPEC-00 §8.3);
  - если это первая задача спеки, смени её статус на `in-progress` в шапке и в индексе SPEC-00 §5;
  - если последняя — проверь критерии приёмки спеки и смени статус на `done`.
- Коммит: `feat(<crate>): T-XX-NN <кратко>` (или `fix`/`test`/`docs`/`chore`). Один коммит на задачу.

## Ключевые правила кода (подробно — SPEC-00 §7)

- Источник никогда не изменяется: скан и бэкап только читают пользовательские файлы (принцип P1).
- Windows-специфичный код — в модулях `win` под `#[cfg(windows)]` с заглушками для других ОС. Логика тестируется кроссплатформенно на `Environment::fake` (SPEC-02 §3.3).
- Ошибки: `thiserror` в библиотеках, `anyhow` только в бинарниках. Без `unwrap()`/`expect()` в библиотечном коде.
- `unsafe` только в `sk-core::win` и `sk-scan::win`, каждый блок с комментарием `// SAFETY:`.
- Файлы ≤ 500 строк.
- Границы крейтов и разрешённые зависимости между ними — SPEC-01 §4.2.
