# Чек-лист приёмки на эталонной машине

| Поле | Значение |
|---|---|
| Основание | SPEC-12 §4.10 (создан в T-12-08) |
| Когда выполнять | перед закрытием фазы P1 и далее перед закрытием каждой фазы и перед релизом |
| Метрики | recall ≥ 90% (SPEC-00 §6, P1); ложные «важные» ≤ 5% выбранного объёма; скан ≤ 60 с на 1 млн файлов (SPEC-00 §6, P1); память ≤ 500 МБ (SPEC-01 NFR-01-02) |

Эталонная машина — реальный Windows-ПК разработчика. По возможности чек-лист повторяется на
чистой VM Windows 10 22H2 и на Windows 11 с тестовыми данными. Каждый прогон — отдельная копия
раздела «Протокол прогона» (§7) с заполненными таблицами. Протоколы с реальными путями и
именами программ хранятся локально и в репозиторий не коммитятся: в репозиторий попадают
только итоговые цифры (§7.4) и задачи на пропуски (§6).

Принцип P1: SaveKeeper только читает. Во время проверки не удалять и не перемещать
пользовательские файлы, чтобы «улучшить» результат.

## 2. Запуск скана

Из папки с портативной сборкой, в Windows PowerShell 5.1 или PowerShell 7, без прав администратора (как обычный пользователь).
Если важные данные лежат на других дисках, добавить `--roots` (SPEC-01 §4.9).

```powershell
# 2.1 Без LLM (это основной прогон для метрик P1)
.\savekeeper-cli.exe scan --llm off --out ref.json --pretty
"exit code: $LASTEXITCODE"      # 0 — успех, 3 — успех с предупреждениями (смотреть issues), 1/2 — прогон невалиден

# 2.2 С локальной LLM (с фазы P2; для сравнения категорий Unknown)
.\savekeeper-cli.exe scan --llm local --out ref-llm.json --pretty
"exit code: $LASTEXITCODE"
```

Записать: версию (`.\savekeeper-cli.exe --version`), коммит сборки, сборку Windows, число
предупреждений (`issues`) и коды выхода.

## 3. Сверка: найдено / неверная категория / не найдено

Для каждого пункта из §1 найти находку в `ref.json` (по `target.resolved`, `target.key`,
`target.exporter_id` или `title`). Быстрый просмотр находок:

```powershell
$r = Get-Content ref.json -Raw | ConvertFrom-Json
$r.findings | Select-Object category, default_selected, title,
  @{n='target'; e={ if ($_.target.resolved) { $_.target.resolved }
                    elseif ($_.target.path) { $_.target.path }
                    elseif ($_.target.key) { $_.target.key }
                    else { $_.target.exporter_id } }},
  @{n='MB'; e={ [math]::Round($_.stats.total_bytes / 1MB, 1) }} |
  Out-GridView
```

Отметки:

| Отметка | Когда ставить |
|---|---|
| ✓ найдено | есть находка, покрывающая пункт целиком (сам путь или родитель после слияния, SPEC-09), категория совпадает с ожидаемой |
| ≈ неверная категория | пункт покрыт находкой, но категория другая (например, `unknown` или `cache` вместо `game_save`) |
| ✗ не найдено | ни одна находка не покрывает пункт (или покрывает только часть файлов) |

Дополнительно для каждого пункта отметить, выбран ли он по умолчанию (`default_selected`).
Сохранения игр из ручного списка должны быть выбраны все (SPEC-09 §8).

Формулы:

- **recall = (✓ + ≈) / всего пунктов**. Цель P1: **≥ 90%**.
- **точность категорий = ✓ / (✓ + ≈)** — фиксируется для отслеживания, отдельного порога нет.

Повторить сверку для `ref-llm.json` (только колонка «отметка с LLM»): ожидается, что часть
`≈` из-за `unknown` переходит в `✓`.

## 4. Ложные «важные»

Пройти все находки с `default_selected = true` и отметить мусор: кэш, логи, временные файлы,
то, что восстанавливается переустановкой или скачиванием, данные удалённых программ без ценности.

```powershell
$sel = $r.findings | Where-Object default_selected
$selBytes = 0; $sel | ForEach-Object { $selBytes += [long]$_.stats.total_bytes }
"selected: $($sel.Count) findings, {0:N1} GB" -f ($selBytes / 1GB)
# сверка с итогами отчёта
$r.totals.all.selected_bytes
```

- **доля ложных = объём находок, отмеченных как мусор / объём всего выбранного по умолчанию**
  (`totals.all.selected_bytes`). Цель: **≤ 5%**.
- Отдельно проверить: среди выбранных по умолчанию нет ни одной находки категорий `cache` и
  `reinstallable`, суммарный объём выбранного по умолчанию ≤ 20 ГБ (SPEC-09 §8).

## 5. Время скана и пиковая память

Запустить прогон без LLM с замером. Перед замером закрыть тяжёлые программы, второй прогон
подряд не делать «холодным» сравнением (учитывать кэш ФС: записать, какой прогон замерялся).

```powershell
$p = Start-Process .\savekeeper-cli.exe -ArgumentList 'scan','--llm','off','--out','perf.json' `
       -PassThru -NoNewWindow
$null = $p.Handle   # cache the handle: without it PS 5.1 loses ExitTime/ExitCode after exit
$peak = 0
while (-not $p.HasExited) {
  $p.Refresh(); $peak = [math]::Max($peak, $p.PeakWorkingSet64); Start-Sleep -Milliseconds 200
}
"wall: {0:N1} s, peak working set: {1:N0} MB, exit: {2}" -f `
  ($p.ExitTime - $p.StartTime).TotalSeconds, ($peak / 1MB), $p.ExitCode

# число файлов в профиле (для приведения к 1 млн файлов)
(Get-ChildItem $env:USERPROFILE -Recurse -File -Force -ErrorAction SilentlyContinue |
  Measure-Object).Count
```

Время скана также видно в отчёте: `finished_at - started_at`. Пиковую память можно
перепроверить в Диспетчере задач (вкладка «Подробности», столбец «Пиковый рабочий набор»).

| Метрика | Порог | Источник |
|---|---|---|
| Время полного скана профиля без LLM на SSD | ≤ 60 с на 1 млн файлов (пересчитать пропорционально числу файлов) | SPEC-00 §6, P1 |
| Пиковая память при скане 1 млн файлов | ≤ 500 МБ | SPEC-01 NFR-01-02 |

## 6. Пропуски → задачи

Каждый `✗` и `≈`, а также каждый ложный «важный» из §4 оформить задачей:

| Причина | Куда |
|---|---|
| Известная программа или игра не покрыта / неверная категория из правила | новое или исправленное правило в `rules/` (SPEC-04) |
| Игра есть в манифесте Ludusavi, но не найдена | SPEC-05 (сверка с `ludusavi backup --preview`) |
| Системная настройка не экспортирована | SPEC-06 |
| Неизвестная папка не распознана или классифицирована неверно | эвристики (SPEC-07) или промпт/LLM (SPEC-08) |
| Мусор выбран по умолчанию | скоринг (SPEC-09) или правило с категорией `cache`/`reinstallable` (SPEC-04) |

В задаче указать: пункт из §1 (без личных данных), фактический результат, ожидаемый результат.
